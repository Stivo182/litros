# Группировка подсистем внутри `src` — дизайн

**Дата:** 2026-07-27
**Статус:** согласованное направление, ожидает проверки спецификации

## Цель

Сделать структуру production-кода понятнее, сгруппировав связанные внутренние
классы по подсистемам. Реорганизация не меняет архитектурные слои проекта,
публичный API, имена типов, DI-контракты или поведение.

## Решение

Верхнеуровневые каталоги `src/cmd`, `src/dto`, `src/repository`, `src/service`,
`src/shared` и `src/web` остаются без изменений: каждый из них уже компактен и
имеет одну понятную ответственность.

Группируется только перегруженный каталог `src/internal/Классы`:

```text
src/
├── main.os
├── cmd/                         # без изменений
├── dto/                         # без изменений
├── internal/
│   ├── Классы/
│   │   ├── БД/
│   │   │   ├── КлассификаторОшибокSQLite.os
│   │   │   ├── КомандаОперацииБД.os
│   │   │   ├── КоординаторОперацийБД.os
│   │   │   ├── НастройкиОтказоустойчивостиБД.os
│   │   │   ├── ОбъектыВзаимодействияСБД.os
│   │   │   ├── ТранзакционныйДоступКБД.os
│   │   │   └── УстойчивыйМенеджерСущностей.os
│   │   ├── GitHub/
│   │   │   ├── КлиентGitHubAPI.os
│   │   │   ├── КомпонентыGitHubAPI.os
│   │   │   └── НастройкиОтказоустойчивостиGitHub.os
│   │   ├── Пакеты/
│   │   │   ├── ВалидаторИмениПакета.os
│   │   │   └── НакопленныеИспользованияПакета.os
│   │   └── СтартерПриложения.os
│   └── Модули/
│       └── РаботаСДаннымиБД.os
├── repository/                  # без изменений
├── service/                     # без изменений
├── shared/                      # без изменений
└── web/                         # без изменений
```

Подпапка создаётся только для связной группы из двух и более файлов.
`СтартерПриложения.os` остаётся непосредственно в `internal/Классы`, поскольку
создавать отдельную папку для одного класса нецелесообразно.

`РаботаСДаннымиБД.os` остаётся в `internal/Модули`. Его неоднородная
ответственность и название требуют отдельного содержательного рефакторинга и не
должны смешиваться с физическим переносом файлов.

## Тесты и документация

Файлы в `tests` не перемещаются. Допускаются только необходимые изменения
содержимого тестов:

- обновление путей в архитектурных проверках, которые читают production-файлы
  по точному расположению;
- корректировка относительного `#Использовать`, только если фактическая загрузка
  после переноса этого потребует;
- усиление structural guard, чтобы он закреплял новые каталоги и запрещал
  возвращение сгруппированных классов в корень `internal/Классы`.

Имена и расположение тестовых наборов и fixtures остаются прежними.

## Совместимость загрузки

OneScript-библиотеки поддерживают вложенные каталоги внутри `Классы`; такой
паттерн уже используется зависимостями проекта. Подключения вида
`#Использовать "../src/internal"` должны продолжить рекурсивно обнаруживать типы.

Несмотря на это, совместимость не считается доказанной структурой каталогов:
после каждого этапа переноса требуется реальная загрузка соответствующих
OneUnit-наборов и финальный полный прогон.

## Неизменяемые контракты

Реорганизация не должна менять:

- имена классов и модулей;
- аннотации Autumn и имена `&Пластилин`-зависимостей;
- количество и сигнатуры экспортных методов;
- resilience pipeline и порядок его стратегий;
- транзакционные и fatal-state гарантии БД;
- публичный класс `СканерИспользованийПакета` и его путь из `packagedef`;
- пути web-ресурсов, DTO, repositories, services и CLI;
- состав production-файлов пакета.

## Сохранение существующих изменений рабочего дерева

До реорганизации в рабочем дереве есть пользовательская незакоммиченная правка
`src/internal/Классы/КлиентGitHubAPI.os`. Этот файл входит в перенос, поэтому
реализация обязана:

1. зафиксировать точный исходный diff пользовательской правки;
2. отделить чистый rename от содержательной правки в индексе;
3. после structural commit оставить тот же пользовательский diff уже по новому
   пути `src/internal/Классы/GitHub/КлиентGitHubAPI.os`;
4. проверить, что пользовательская правка не попала в commit и не потерялась.

Остальные известные изменения `packagedef`, production
`ХранилищеОчередиПакетов.os` и generated `litros.log` также не входят в задачу.

## Проверка

Реализация должна подтвердить:

1. каждый перенесённый тип загружается по прежнему имени;
2. Autumn создаёт DB- и GitHub-компоненты после изменения путей;
3. архитектурные проверки читают файлы из новых каталогов;
4. старые production-пути отсутствуют, а новые содержат полный ожидаемый набор;
5. `oscript -check` проходит для всех перемещённых `.os`;
6. полный OneUnit-прогон успешен;
7. индекс содержит только согласованные rename и точечные изменения путей;
8. пользовательские незакоммиченные изменения сохранены вне commit.

## Вне области задачи

- перенос или группировка тестовых файлов и fixtures;
- переименование классов, модулей и верхнеуровневых каталогов;
- feature-first или domain-first перестройка проекта;
- декомпозиция `КлиентGitHubAPI.os`;
- разделение или переименование `РаботаСДаннымиБД.os`;
- изменение зависимостей, публичного API или runtime-поведения.
