# Встраивание DB executor в устойчивый фасад Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Удалить отдельный `ИсполнительОперацийБД`, перенести resilience pipeline в `УстойчивыйМенеджерСущностей` и заменить структурную команду единым неизменяемым классом `КомандаОперацииБД`.

**Architecture:** Фасад сохраняет шесть прикладных экспортов, добавляет один служебный retry-callback и владеет pipeline повторов/ограничения параллелизма. `КоординаторОперацийБД` продолжает выполнять одну DB-попытку и владеть raw-менеджером, транзакцией и fatal-state; между ними передаётся валидированная `КомандаОперацииБД`.

**Tech Stack:** OneScript, Autumn, resilience, entity, OneUnit, asserts, moskito, reflector, SQLite.

---

`packagedef`, `КлиентGitHubAPI.os` и `ХранилищеОчередиПакетов.os`; для repository
меняется только его тестовый wiring.
